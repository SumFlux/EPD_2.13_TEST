# 前端图片模块对接指南

本文档详细说明了如何对接后端新增的**自定义图片管理**与**实时预览**功能。前端可基于此实现一个完整的“墨水屏图片编辑器”。

## 1. 核心流程概述

为了让用户在上传前能看到最终在墨水屏（2.13寸, 250x122, 黑白双色）上的显示效果，建议采用以下交互流程：

1.  **选择图片**: 用户从本地选择一张图片。
2.  **编辑与预览**:
    *   前端提供裁剪框、旋转按钮、阈值滑块、反色开关等控件。
    *   当用户调整参数时，调用 **预览接口** 获取处理后的效果图（建议防抖）。
3.  **确认上传**:
    *   用户点击“保存”时，将最终的参数和原图文件调用 **上传接口**。

## 2. API 接口详解

### 2.1 实时预览接口 (Preview)

用于获取带处理效果的预览图，**不会保存到数据库**。

*   **URL**: `POST /api/v1/images/preview`
*   **Content-Type**: `multipart/form-data`

#### 请求参数 (Form Data)

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `file` | File | 是 | 原始图片文件 (png/jpg/jpeg) |
| `options` | JSON String | 否 | 处理参数对象 (见下方说明) |

#### `options` 参数结构

需要将 JSON 对象序列化为字符串传给 `options` 字段：

```json
{
  "rotate": 90,           // 旋转角度: 0, 90, 180, 270
  "crop_x": 10,           // 裁剪起点 X (相对于原图)
  "crop_y": 20,           // 裁剪起点 Y
  "crop_w": 200,          // 裁剪宽度
  "crop_h": 100,          // 裁剪高度
  "invert": false,        // 是否反色: true/false
  "dither": true,         // 二值化模式: true=抖动(适合照片), false=阈值(适合文字)
  "threshold": 128        // 阈值: 0-255 (仅当 dither=false 时生效)
}
```

#### 响应
*   **Success (200)**: 返回 `image/png` 二进制流。前端可直接通过 `URL.createObjectURL(blob)` 显示。
*   **Error (400)**: JSON 格式错误信息。

#### 前端调用示例 (JavaScript)

```javascript
async function getPreview(file, options) {
  const formData = new FormData();
  formData.append('file', file);
  // 注意：options 必须是 JSON 字符串
  formData.append('options', JSON.stringify(options));

  const response = await fetch('/api/v1/images/preview', {
    method: 'POST',
    headers: {
      'Authorization': 'Bearer <token>'
    },
    body: formData
  });

  if (response.ok) {
    const blob = await response.blob();
    return URL.createObjectURL(blob); // 返回可用于 <img src="..."> 的 URL
  }
}
```

### 2.2 上传图片接口 (Upload)

上传并保存图片，服务器会根据传入的 `options` 进行永久处理并存储。

*   **URL**: `POST /api/v1/images/`
*   **Content-Type**: `multipart/form-data`

#### 请求参数
与预览接口完全一致。
*   `file`: 原图
*   `options`: JSON 字符串 (包含最终确定的裁剪、旋转、二值化参数)

#### 响应
*   **Success (200)**:

```json
{
  "id": 12,
  "url": "/assets/custom_images/1/xxxx.png",  // 最终保存的图片 URL
  "display_order": 1,
  "view_count": 0,
  "created_at": "2026-02-04T12:00:00"
}
```

---

### 2.3 获取图片列表

*   **URL**: `GET /api/v1/images/`
*   **响应**: 图片对象数组。

### 2.4 图片排序

*   **URL**: `PUT /api/v1/images/reorder`
*   **Body**:
```json
[
  { "id": 12, "new_order": 1 },
  { "id": 10, "new_order": 2 }
]
```

### 2.5 删除图片

*   **URL**: `DELETE /api/v1/images/{id}`

## 3. 前端编辑器建议

### 3.1 裁剪交互
建议使用开源库如 `cropperjs` 或 `react-cropper`。
*   **锁定比例**: 设置裁剪框宽高比为 `250 / 122` (约 2.05:1)，确保裁剪内容完美适配屏幕。
*   **获取坐标**: 使用库提供的 `getData()` 方法获取 `x, y, width, height`，传给后端的 `crop_x` 等参数。

### 3.2 模式选择逻辑
提供一个开关切换“照片模式”与“文字模式”：
*   **照片模式**: 设置 `dither: true` (隐藏阈值滑块)。后端使用 Floyd-Steinberg 抖动算法，适合显示细节丰富的照片。
*   **文字模式**: 设置 `dither: false` (显示阈值滑块)。后端使用二值化阈值处理，线条更清晰。

### 3.3 预览防抖
由于预览需要上传图片并进行图像处理，建议在用户拖动滑块时使用 `debounce` (防抖) 技术，延迟 300-500ms 再发送请求，避免频繁请求导致卡顿。

```javascript
// 简单防抖示例
let timeout;
function onSliderChange(value) {
  clearTimeout(timeout);
  timeout = setTimeout(() => {
    updatePreview(value);
  }, 500);
}
```

## 4. 设备端显示原理

虽然前端主要通过 API 交互，但了解后端处理逻辑有助于调试：
1.  后端接收原图 + `options`。
2.  先执行**旋转**。
3.  执行**裁剪** (如果提供了 crop 参数)，否则执行 **Aspect Fill** (等比填充居中)。
4.  强制**缩放**至 250x122 像素。
5.  转为**灰度**，根据 `dither` 参数执行抖动或阈值处理。
6.  最终生成一张 **1-bit 深度** 的 PNG 图片供前端显示。
7.  当设备请求数据时，后端会将这张 PNG 转为 **ESP32 驱动可读的 Buffer** (Horizontal, MSB first)。
