# 系统运维与操作指南

本文档提供了 Infinity Tag 后端服务的部署、维护、备份及故障排查指南，适用于运维人员或系统管理员。

## 1. 服务管理 (Docker Compose)

所有操作均在项目根目录下执行。

### 启动服务
首次部署或重启所有服务：
```bash
# -d 表示后台运行
docker-compose up -d
```
*启动后，系统会自动拉取镜像、创建数据库、初始化网络。*

### 停止服务
```bash
docker-compose down
```

### 重启特定服务
仅重启后端应用（代码更新后）：
```bash
docker-compose restart backend
```

### 查看服务状态
```bash
docker-compose ps
```

---

## 2. 日志监控

查看服务运行日志是排查问题的首要手段。

### 实时查看所有日志
```bash
# -f 表示 follow (实时刷新)
docker-compose logs -f
```

### 查看特定服务日志
```bash
# 仅查看后端应用日志，显示最后 100 行
docker-compose logs -f --tail=100 backend

# 查看数据库日志
docker-compose logs -f mysql
```

## 3. 数据备份与恢复

本系统核心数据存储在 Docker Volume 中：
-   `mysql-data`: 用户档案、鉴权信息
-   `redis-data`: 缓存、限流计数器

### 3.1 数据库备份 (MySQL)
建议设置定时任务 (Cron) 每日执行。

```bash
# 导出 SQL 文件 (在宿主机执行)
docker exec infinitytag-mysql mysqldump -u root -p<PASSWORD> infinity_tag > backup_$(date +%F).sql
```
*注意*: 请将 `<PASSWORD>` 替换为 `.env` 文件中的 `MYSQL_ROOT_PASSWORD`。

### 3.2 数据库恢复

```bash
# 1. 停止后端服务防止写入
docker-compose stop backend

# 2. 导入 SQL 数据
cat backup_2026-xx-xx.sql | docker exec -i infinitytag-mysql mysql -u root -p<PASSWORD> infinity_tag

# 3. 重启后端
docker-compose start backend
```

## 4. 版本更新流程

当代码仓库有新代码提交时，请按以下步骤更新生产环境：

1.  **拉取最新代码**:
    ```bash
    git pull origin main
    ```

2.  **重建镜像**:
    ```bash
    docker-compose build backend
    ```

3.  **应用更新**:
    ```bash
    # Docker Compose 会自动重建容器并重启
    docker-compose up -d
    ```

4.  **检查数据库迁移**:
    如果代码包含数据库变更，容器启动脚本会自动运行迁移。检查日志确认成功：
    ```bash
    docker-compose logs backend | grep "Running migrations"
    ```

## 5. 常见问题排查 (Troubleshooting)

### Q1: API 返回 "Database connection failed"
-   **检查**: MySQL 容器是否运行 (`docker-compose ps`)。
-   **检查**: `.env` 中的数据库密码是否与 Docker 容器内一致。
-   **解决**: 查看 MySQL 日志 `docker-compose logs mysql` 寻找报错原因。

### Q2: AI 生成失败 / 响应慢
-   **检查**: 确保服务器能访问外网（AI API 地址）。
-   **检查**: 查看后端日志，搜索 "OpenAI API Error"。
-   **解决**: 检查 `.env` 中的 `AI_API_KEY` 余额或有效性。

### Q3: 设备无法连接 (Connection Refused)
-   **检查**: 防火墙是否放行了 80/443 (Nginx) 或 8000 (Backend) 端口。
-   **检查**: 如果是云服务器，检查安全组设置。

### Q4: 忘记 Admin 密码或需要重置数据
-   **操作**: 若需彻底重置，可删除数据卷（**警告：数据将丢失**）：
    ```bash
    docker-compose down -v
    docker-compose up -d
    ```
