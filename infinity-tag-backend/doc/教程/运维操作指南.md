## 1. 服务管理

所有操作均在项目根目录下执行。

### 1.1 Docker Compose 方式

#### 启动服务
首次部署或重启所有服务：
```bash
docker compose up -d
```

#### 停止服务
```bash
docker compose down
```

#### 重启特定服务
仅重启后端应用（代码更新后）：
```bash
docker compose restart backend
```

#### 查看服务状态
```bash
docker compose ps
```

---

### 1.2 本地开发模式

#### 启动数据库
```bash
# 仅启动 MySQL 和 Redis
docker compose up -d mysql redis
```

#### 启动后端服务
```bash
# Windows
venv\Scripts\activate
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# Linux/macOS
source venv/bin/activate
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

#### 停止服务
- 后端: 在终端按 `Ctrl+C`
- 数据库: `docker compose down`

## 2. 日志监控

查看服务运行日志是排查问题的首要手段。

### 2.1 Docker 日志

**实时查看所有日志**:
```bash
docker compose logs -f
```

**查看特定服务日志**:
```bash
# 查看后端应用日志，显示最后 100 行
docker compose logs -f --tail=100 backend

# 查看数据库日志
docker compose logs -f mysql

# 查看 Redis 日志
docker compose logs -f redis
```

---

### 2.2 本地日志

后端服务的日志会输出到标准输出（终端）。

**生产环境建议**使用 Supervisor 或 systemd 将日志重定向到文件：
```bash
# Supervisor 配置示例
stderr_logfile=/var/log/infinity-tag.err.log
stdout_logfile=/var/log/infinity-tag.out.log
```

## 3. 数据备份与恢复

本系统核心数据存储在以下位置：
- **MySQL Volume**: `mysql-data` (用户档案、黄历记录、图片元数据)
- **Redis Volume**: `redis-data` (缓存、限流计数器)
- **静态文件**: `assets/custom_images/` (用户上传的图片文件)

---

### 3.1 数据库备份 (MySQL)

**手动备份**:
```bash
# 导出 SQL 文件
docker exec infinitytag-mysql mysqldump -u root -p<PASSWORD> infinity_tag > backup_$(date +%F).sql
```

**自动备份 (Cron)**:

创建备份脚本 `/opt/backup-infinity-tag.sh`:
```bash
#!/bin/bash
BACKUP_DIR="/var/backups/infinity-tag"
DATE=$(date +%F)
PASSWORD="your_mysql_root_password"

mkdir -p $BACKUP_DIR

# 备份数据库
docker exec infinitytag-mysql mysqldump -u root -p$PASSWORD infinity_tag > $BACKUP_DIR/db_$DATE.sql

# 备份图片文件
tar -czf $BACKUP_DIR/assets_$DATE.tar.gz -C /var/www/infinity-tag/assets .

# 删除 30 天前的备份
find $BACKUP_DIR -type f -mtime +30 -delete

echo "Backup completed: $DATE"
```

添加到 Cron（每日凌晨 2 点执行）:
```bash
chmod +x /opt/backup-infinity-tag.sh
crontab -e

# 添加以下行
0 2 * * * /opt/backup-infinity-tag.sh >> /var/log/infinity-tag-backup.log 2>&1
```

---

### 3.2 数据库恢复

```bash
# 1. 停止后端服务防止写入
docker compose stop backend

# 2. 导入 SQL 数据
cat backup_2026-02-04.sql | docker exec -i infinitytag-mysql mysql -u root -p<PASSWORD> infinity_tag

# 3. 重启后端
docker compose start backend
```

---

### 3.3 图片文件备份与恢复

**备份**:
```bash
# 压缩整个 assets 目录
tar -czf assets_backup_$(date +%F).tar.gz -C /var/www/infinity-tag assets
```

**恢复**:
```bash
# 解压到项目目录
tar -xzf assets_backup_2026-02-04.tar.gz -C /var/www/infinity-tag

# 设置权限 (Linux)
sudo chown -R www-data:www-data /var/www/infinity-tag/assets
```

## 4. 版本更新流程

当代码仓库有新代码提交时，请按以下步骤更新生产环境：

### 4.1 Docker 部署更新

```bash
# 1. 拉取最新代码
git pull origin main

# 2. 重建镜像
docker compose build backend

# 3. 应用更新（会自动重启容器）
docker compose up -d

# 4. 检查数据库迁移
docker compose logs backend | grep "Running migrations"
```

---

### 4.2 本地部署更新

```bash
# 1. 拉取最新代码
git pull origin main

# 2. 激活虚拟环境并更新依赖
source venv/bin/activate  # Linux/macOS
# 或 venv\Scripts\activate  # Windows
pip install -r requirements.txt

# 3. 应用数据库迁移
alembic upgrade head

# 4. 重启后端服务
# Supervisor: sudo supervisorctl restart infinity-tag
# 手动: Ctrl+C 然后重新运行 uvicorn
```

## 5. 存储空间管理（新增）

从 v1.1 开始，用户可以上传自定义图片，需要定期监控存储空间。

### 5.1 监控存储使用情况

```bash
# 查看 assets 目录占用空间
du -sh /var/www/infinity-tag/assets

# 查看每个用户的图片占用空间
du -sh /var/www/infinity-tag/assets/custom_images/*

# 查看 Docker Volume 占用
docker system df -v
```

---

### 5.2 清理策略

**手动清理未使用的图片**:
```bash
# 进入 Python shell
python
>>> from app.core.database import get_db
>>> from app.models.image import CustomImage
>>> import os
>>> # 获取数据库中所有图片路径
>>> # 对比 assets 目录，删除孤立文件
```

**设置存储配额** (建议在应用层实现):
- 每个用户最多 5 张图片（已实现）
- 每张图片最大 5MB（建议在前端和后端校验）
- 定期归档 90 天未访问的图片

---

### 5.3 磁盘空间告警

**监控脚本示例** (`/opt/check-disk-space.sh`):
```bash
#!/bin/bash
THRESHOLD=80
USAGE=$(df -h / | tail -1 | awk '{print $5}' | sed 's/%//')

if [ $USAGE -gt $THRESHOLD ]; then
  echo "ALERT: Disk usage at ${USAGE}%" | mail -s "Disk Space Warning" admin@infinitytag.app
fi
```

添加到 Cron:
```bash
*/30 * * * * /opt/check-disk-space.sh
```

## 6. 常见问题排查 (Troubleshooting)

### Q1: API 返回 "Database connection failed"

**检查**:
```bash
# 检查 MySQL 容器是否运行
docker compose ps

# 查看 MySQL 日志
docker compose logs mysql
```

**解决**:
- 确认 `.env` 中的数据库密码与 Docker Compose 配置一致
- 重启 MySQL: `docker compose restart mysql`

---

### Q2: AI 生成失败 / 响应慢

**检查**:
```bash
# 测试外网连接
curl -I https://www.dmxapi.cn

# 查看后端日志
docker compose logs backend | grep "AI"
```

**解决**:
- 检查 `.env` 中的 `AI_API_KEY` 余额
- 增加超时时间: `AI_TIMEOUT=120`
- 检查服务器网络是否能访问外网

---

### Q3: 设备无法连接 (Connection Refused)

**检查**:
```bash
# 检查端口监听
netstat -tuln | grep 8000

# Windows
netstat -ano | findstr ":8000"
```

**解决**:
- 防火墙放行 80/443 (Nginx) 或 8000 (Backend) 端口
- 云服务器检查安全组设置

---

### Q4: 图片上传失败或无法访问

**现象**: 上传接口返回 500 错误或图片 URL 返回 404。

**检查**:
```bash
# 检查 assets 目录权限 (Linux)
ls -la /var/www/infinity-tag/assets

# 检查后端日志
docker compose logs backend | grep "image"
```

**解决**:
```bash
# 创建目录并设置权限
mkdir -p /var/www/infinity-tag/assets/custom_images
sudo chown -R www-data:www-data /var/www/infinity-tag/assets
sudo chmod -R 755 /var/www/infinity-tag/assets
```

---

### Q5: 图片处理内存溢出

**现象**: 后端日志显示 "MemoryError" 或容器频繁重启。

**原因**: 用户上传超大图片（如 10MB+ 的高分辨率照片）。

**解决**:
1. 在前端限制上传文件大小（建议 5MB 以内）
2. 在后端增加图片尺寸检查（已实现：`MAX_PIXELS = 4000000`）
3. 增加 Docker 容器内存限制:
```yaml
# docker-compose.yml
services:
  backend:
    deploy:
      resources:
        limits:
          memory: 1G
```

---

### Q6: 忘记数据库密码或需要重置数据

**操作**: 若需彻底重置，可删除数据卷（**警告：数据将丢失**）:
```bash
docker compose down -v
docker compose up -d
```

---

### Q7: Nginx 502 Bad Gateway

**原因**: 后端服务未启动或端口配置错误。

**检查**:
```bash
# 检查后端是否运行
docker compose ps backend

# 检查 Nginx 配置
docker compose exec nginx cat /etc/nginx/nginx.conf
```

**解决**:
- 确保后端监听在 `127.0.0.1:8000`
- 检查 Nginx upstream 配置指向正确的后端地址
