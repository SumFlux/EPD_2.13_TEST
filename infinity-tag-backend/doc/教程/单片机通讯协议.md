# 单片机 (MCU) 通讯与开发指南

本文档专为嵌入式开发人员设计，详细说明了 Infinity Tag 墨水屏设备与后端服务器交互的完整流程、协议细节及异常处理策略。

## 1. 通讯流程概览

设备端的核心工作流如下：

1.  **网络初始化**: 连接 WiFi，同步网络时间 (NTP)。
2.  **身份认证**:
    -   检查本地是否存储有效的 `access_token`。
    -   **有 Token**: 直接进入数据请求阶段。
    -   **无 Token / Token 失效**: 调用激活接口获取新 Token 并存储。
3.  **数据请求**: 使用 Token 请求黄历或运势数据。
4.  **数据解析**: 解析 JSON 响应，提取关键文本 (UTF-8)。
5.  **屏幕刷新**: 将文本渲染并刷新到墨水屏。
6.  **休眠/待机**: 进入低功耗模式，等待下次唤醒。

## 2. 关键接口实现

### 2.1 设备激活 (获取 Token)

设备首次启动或 Token 过期（HTTP 401）时调用。

-   **接口**: `POST /api/v1/auth/activate`
-   **Content-Type**: `application/json`

**请求示例**:
```json
{
  "device_code": "123456",     // 出厂烧录或生成的6位唯一码
  "device_uuid": "MAC_ADDR_HASH" // 可选：MCU的唯一硬件ID
}
```

**处理逻辑**:
1.  发送 HTTPS POST 请求。
2.  解析响应中的 `data.access_token`。
3.  **关键步骤**: 将 Token 写入非易失性存储器 (EEPROM/Flash/NVS)。
    -   *注意*: Token 长度可能较长 (约 150-200 字节)，请预留足够的存储空间。

### 2.2 获取今日黄历

这是设备最常用的接口，用于获取当天的运势信息。

-   **接口**: `POST /api/v1/almanac/generate`
-   **Header**: `Authorization: Bearer <Stored_Token>`

**请求示例**:
```json
{
  "target_date": "2026-02-03" // 可选，不传默认为服务器当前时间
}
```

**响应主要字段解析**:
```json
{
  "data": {
    "lunar_date_str": "丙午年正月初七",  // 农历日期
    "daily_fortune": "今日财运亨通...",      // 核心运势文案 (UTF-8)
    "lucky_color": "琥珀色",                // 幸运色
    "wealth_score": 88,                    // 财运分 (0-100)
    "auspicious": ["签约", "搬家"]          // 宜 (数组)
  }
}
```

## 3. 异常处理策略 (Robustness)

嵌入式环境网络不稳定，必须做好异常处理。

### 3.1 HTTP 状态码处理

| 状态码 | 含义 | 建议动作 |
|---|---|---|
| **200** | 成功 | 解析 JSON，重置错误计数器。 |
| **401** | 未授权 | Token 过期或无效。**动作**: 清除本地 Token，重新发起“设备激活”流程，获取新 Token。 |
| **429** | 请求过多 | 触发限流。**动作**: 休眠 5-10 分钟后重试，避免死循环请求。 |
| **500+** | 服务器错误 | **动作**: 保持屏幕显示上次缓存的内容或错误图标，休眠 1 小时后重试。 |

### 3.2 网络故障处理

如果 WiFi 连接失败或 DNS 解析失败：
1.  **重试机制**: 建议重试 3 次，每次间隔 2-5 秒。
2.  **离线模式**: 如果彻底断网，屏幕应显示本地缓存的“万年历”数据（如果有）或特定的“离线图标”，避免白屏。

## 4. 开发注意事项

### 4.1 JSON 解析
MCU 资源有限 (如 ESP32/ESP8266)，建议使用流式解析库或轻量级库 (如 `cJSON`, `ArduinoJson`)。
-   **内存预估**: 完整响应包可能在 1KB-2KB 之间，确保堆栈内存充足 (建议预留 4KB 缓冲区)。

### 4.2 字符编码 (UTF-8)
后端返回的所有中文均为 **UTF-8 编码**。
-   如果使用点阵字库 (GB2312/GBK)，需要包含 **UTF-8 转 GBK** 的转换函数。
-   如果使用矢量字体 (如 Freetype)，直接支持 UTF-8 即可。

### 4.3 HTTPS SSL/TLS
-   生产环境强制 HTTPS。
-   **证书验证**: 建议在 MCU 中根据资源情况选择“跳过证书验证” (insecure) 或“内置根证书”。如果验证证书，请务必同步网络时间 (NTP)，否则会导致握手失败。

### 4.4 功耗控制
-   完成数据获取和屏幕刷新后，务必立即关闭 WiFi 模组并进入 Deep Sleep 模式。
-   建议刷新频率：每天凌晨 0:05 自动唤醒刷新一次，或用户按键手动刷新。
