# 开发规范

## 语言与提交
- 所有回复与说明统一使用简体中文。
- 所有 commit message 必须使用简体中文描述修改内容（标题中文，必要英文可放正文或文档）。

## 开发工作流程

### 标准开发流程
遵循以下标准化流程确保代码质量和文档一致性：

1. **代码开发阶段**
   - 完成功能开发或问题修复
   - 进行基本的类型检查和构建验证
   - 代码修改完成后等待用户测试

2. **用户测试阶段**
   - 用户进行功能测试和验证
   - 根据测试反馈进行必要的调整
   - 用户确认功能符合预期

3. **文档与提交阶段**（仅在用户说"可以提交"时执行）
   - 更新 `memory-bank/progress.md` - 记录具体改动和任务进展
   - 更新 `memory-bank/architecture.md` - 补充新的架构洞察和技术说明
   - 执行 `git commit` 提交所有更改

### 流程优势
- **质量保障**：只为经过测试验证的功能编写文档
- **避免浪费**：防止为可能需要调整的代码写无效文档
- **用户参与**：确保最终交付的功能符合用户预期
- **版本一致**：代码、文档、commit信息保持同步


## 文档同步要求
- 代码修改完成且用户确认提交时：
  1. 在 `memory-bank/progress.md` 记录具体改动/任务进展。
  2. 在 `memory-bank/architecture.md` 补充新的架构洞察，说明新增或修改文件的作用。

### 测试文档同步
- 在 `backend/scripts/` 新增脚本后，必须同步更新 `doc/教程/测试脚本使用指南.md`
