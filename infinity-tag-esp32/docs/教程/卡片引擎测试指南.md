# Infinity Tag Lua卡片引擎测试指南

## 1. 编译与固件上传

### 1.1 编译固件
在VS Code的终端中执行以下命令，确保没有编译错误：
```bash
pio run
```

### 1.2 上传固件
连接设备，执行以下命令将固件烧录到ESP32：
```bash
pio run -t upload
```

### 1.3 监控串口输出
上传完成后，立即打开串口监视器，观察启动日志：
```bash
pio device monitor
```
**关键检查点：**
- [ ] 看到 `[LuaEngine] Initialized successfully`
- [ ] 看到 `[LuaBindings] GFXCanvas1 allocated` (这是我们刚才修复的关键点)
- [ ] 看到 `[Cards] Loaded Lua card: calendar.lua`

## 2. 上传文件系统 (LittleFS)

Lua脚本和资源文件存储在 `data/` 目录下，如果不上传文件系统，Lua卡片将无法加载。

### 2.1 执行上传命令
关闭串口监视器（如果已打开），然后执行：
```bash
pio run -t uploadfs
```
此操作会将 `data/` 目录下的所有文件打包并上传到ESP32的LittleFS分区。

## 3. 功能验证

### 3.1 黄历卡片 (calendar.lua)
- **现象**：设备启动后，如果默认进入黄历卡片，屏幕应显示 "今日黄历"、日期和宜忌信息。
- **交互测试**：
  - **按键 (Button)**：短按按键，观察串口输出 `Button pressed - refreshing calendar`，屏幕应刷新。
  - **摇一摇 (Shake)**：摇动设备，观察串口输出 `Device shaken - refreshing`，屏幕应刷新。

### 3.2 切换卡片
- **长按按键**：长按按键1秒以上，进入卡片切换模式。
- **滚轮操作**：旋转编码器，应能看到卡片图标和名称（如 "黄历"、"图片"、"模板"）在屏幕上切换。
- **选择卡片**：短按按键确认选择。

### 3.3 图片卡片 (image.lua)
- **加载**：切换到图片卡片。
- **现象**：屏幕应显示一张位图图片（如果有 `data/images/test.bin`）。
- **网络图片**：按键触发 HTTP 下载位图并在屏幕上显示（需观察串口 `[Lua] Downloading bitmap...`）。

## 4. 故障排查

### 4.1 屏幕显示 "Lua Card Error"
- **原因**：脚本加载失败或运行时错误。
- **解决**：检查串口日志中的 `ERROR:` 信息，通常是语法错误或 API 调用参数错误。

### 4.2 串口显示 "Framebuffer not initialized"
- **原因**：内存不足或初始化顺序错误。
- **解决**：我们已通过 `GFXCanvas1` 修复此问题，如果仍出现，请检查 PSRAM 是否启用（`build_flags` 中要有 `-DBOARD_HAS_PSRAM`）。

### 4.3 无法连接 WiFi
- **原因**：配置未保存或信号弱。
- **解决**：观察启动时的 `[WiFi]` 日志，必要时重新配网。

## 5. 开发新的 Lua 卡片

### 5.1 创建脚本
在 `data/cards/` 目录下新建 `.lua` 文件，例如 `my_test.lua`：

```lua
CARD_NAME = "测试卡片"
CARD_CATEGORY = "工具"
CARD_LOGO = "/icons/card_default.bin"

function onInit()
    sys.log("Init")
    eink.clear()
    eink.drawStr(10, 50, "Hello World")
    eink.drawRect(5, 5, 200, 90)
    eink.refresh()
end

function onBtnPress()
    eink.clear()
    eink.drawChinese(50, 40, "按键触发")
    eink.refresh()
end
```

### 5.2 重新上传
每次修改 Lua 脚本后，必须重新执行：
```bash
pio run -t uploadfs
```
不需要重新编译固件。
